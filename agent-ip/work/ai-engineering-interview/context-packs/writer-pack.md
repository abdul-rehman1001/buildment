## 4. Assessments

### MCQ fence (exact)
````
```quiz
type: mcq
question: "<scenario with a decision, not recall>"
options:
  - "<option>"
  - "<option>"
  - "<option>"
  - "<option>"
correct: <0-based index>
explanations:
  - "<why this option is right or wrong, standalone>"
  - "..."
  - "..."
  - "..."
```
````
- Four options. One reason per option, in option order, each a standalone sentence or two. The right one may start with "Right."
- Test application in a scenario, not recall of a sentence above.
- **Option length:** the correct option must not be longer than the longest wrong option (aim within a few characters, and never 10% longer). Across a quiz chapter, the correct option must be the strictly longest in at most one of five questions. Write all options at the same level of detail: if one is a full sentence, all are. Vary the correct position (use each of 0 to 3 at least once in a quiz chapter).
- No "all of the above", no joke options, no negatives like "Which is NOT".
- **Opinion goes to an open question.** If a reasonable senior engineer could pick a different option, do not grade it. Each graded key must be defensible by a fact or a clearly stated rule in the course.
- **Blind re-answer:** after writing each MCQ, cover the key and answer it again from the question and options alone. If you hesitate between two options, rewrite. An independent blind review will re-answer every key later.
- Quote YAML strings with double quotes. Do not use a double quote inside a string; use single quotes inside instead. Avoid a colon followed by a space inside unquoted text (always quote).

### Predict fence (exact; exactly two options)
````
```predict
prompt: "<a specific decision in this chapter's scenario>"
options:
  - id: <short-id>
    label: "<option>"
  - id: <short-id>
    label: "<option>"
correctOptionId: <id>
explanation: "<why, in one or two sentences>"
```
````
The correct label must not be longer than the other. Place it right before the explanation it prepares.

### Open question fence
````
```openquestion
prompt: "<what to write, with the parts to include>"
required: true
minWords: <honest minimum>
allowSpeechInput: true
modelAnswer: "<a strong answer showing the shape, with numbers>"
```
````
`modelAnswer` is shown to mentors and after submission. Write it as a real, strong answer for a fictional project (not the learner's).

## 8. Facts to get right (verified 2026-10-22)

- LangGraph 1.2.16: `from langgraph.graph import StateGraph, START, END`; `from langgraph.graph.message import add_messages`; state as a `TypedDict` with `Annotated[list, add_messages]` or `Annotated[list, operator.add]`; a key without a reducer is overwritten; two parallel nodes writing the same non-reducer key in one step raise `InvalidUpdateError`; `from langgraph.types import interrupt, Command`; `interrupt(value)` pauses and needs a checkpointer; resume with `graph.invoke(Command(resume=...), config)` using the same `{"configurable": {"thread_id": ...}}`; `from langgraph.checkpoint.memory import InMemorySaver`. - Python 3.11 added `asyncio.timeout()` and `asyncio.TaskGroup`; `asyncio.wait_for` and `asyncio.gather` also exist.
- MCP: an open protocol (JSON-RPC 2.0 messages) between a host application's client and servers that expose tools, resources and prompts; transports include stdio for local servers and streamable HTTP for remote ones. Do not claim more detail than this without checking the specification.
- Metrics: recall@k = relevant items in the top k divided by all relevant items; precision@k = relevant items in the top k divided by k; reciprocal rank = 1 divided by the rank of the first relevant item (0 if none); MRR = mean of reciprocal ranks over queries. Reciprocal rank fusion score = sum over lists of 1 / (60 + rank), with 60 the common default constant.
