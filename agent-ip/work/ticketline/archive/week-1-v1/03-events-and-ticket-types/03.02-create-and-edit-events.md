## The event that started an hour late

An organizer in New York creates an event for 7:00 p.m. on March 8, 2026. The form sends `2026-03-08T19:00:00` with no zone. The server stores it as UTC. The public page renders 3:00 p.m. New York time. The venue opens at 7:00 p.m.; attendees arrive at 3:00 p.m.

The bug is not the date picker. The bug is a missing time-zone contract. Ticketline stores every instant in UTC and stores the event's IANA zone for display and validation.

<BigWordAlert
  term="IANA time zone"
  plainEnglish="A named region with historical daylight-saving rules, such as America/New_York or Europe/London."
  whyItMatters="An offset like -05:00 is wrong half the year. A named zone lets the system display the correct local time across DST changes."
/>

## The event payload

Create `packages/shared/src/event.ts` so the API and web app share the same contract:

```ts
import { z } from "zod";

const isValidTimeZone = (value: string) => {
  try {
    new Intl.DateTimeFormat(undefined, { timeZone: value });
    return true;
  } catch {
    return false;
  }
};

export const eventInputSchema = z
  .object({
    title: z.string().trim().min(3).max(140),
    description: z.string().trim().min(20).max(5000),
    venueName: z.string().trim().min(1).max(140),
    venueAddress: z.string().trim().min(3).max(300),
    timezone: z.string().refine(isValidTimeZone, "Use a valid IANA time zone."),
    startsAt: z.coerce.date(),
    endsAt: z.coerce.date(),
    salesStartAt: z.coerce.date(),
    salesEndAt: z.coerce.date(),
  })
  .refine((value) => value.endsAt > value.startsAt, {
    message: "The event must end after it starts.",
    path: ["endsAt"],
  })
  .refine((value) => value.salesEndAt > value.salesStartAt, {
    message: "The sale window is invalid.",
    path: ["salesEndAt"],
  })
  .refine((value) => value.salesEndAt <= value.startsAt, {
    message: "Sales must close before the event starts.",
    path: ["salesEndAt"],
  });

export type EventInput = z.infer<typeof eventInputSchema>;
```

The web form should send ISO instants with `Z` or an explicit offset, plus the IANA zone. The API re-validates everything; the client is not trusted.

## Slugs

A slug is a human-readable URL key. It must be unique and stable enough to share.

```ts
import { randomBytes } from "node:crypto";

export function slugify(title: string) {
  const base = title
    .toLowerCase()
    .trim()
    .replace(/[^a-z0-9]+/g, "-")
    .replace(/^-+|-+$/g, "")
    .slice(0, 48);

  return `${base || "event"}-${randomBytes(3).toString("hex")}`;
}
```

Do not use the title alone. Two organizers can run "Summer Live" on the same night. The random suffix keeps the slug unique without a database round trip; the unique constraint is the final guard.

## Create

```ts
organizerEventRouter.post("/events", async (req, res, next) => {
  try {
    const input = eventInputSchema.parse(req.body);

    const event = await prisma.event.create({
      data: {
        ...input,
        organizerId: req.user!.id,
        slug: slugify(input.title),
      },
    });

    res.status(201).json({ success: true, data: event });
  } catch (error) {
    next(error);
  }
});
```

`organizerId` comes from the session. If the request body contains an `organizerId`, Zod strips it because the schema does not include it. Do not spread untrusted input into the create data.

## Edit

```ts
organizerEventRouter.patch("/events/:id", async (req, res, next) => {
  try {
    const event = await loadOwnedEvent(req.user!, req.params.id);
    const input = eventInputSchema.partial().parse(req.body);

    const updated = await prisma.event.update({
      where: { id: event.id },
      data: input,
    });

    res.json({ success: true, data: updated });
  } catch (error) {
    next(error);
  }
});
```

If the event is published and has orders, editing the date or venue may require a warning or a new version. Ticketline v1 allows the edit but records it in `updatedAt`; the course discusses the gap in Week 4. Do not silently change the price of an existing ticket type; price snapshots arrive in Module 5.

## List only your events

```ts
organizerEventRouter.get("/events", async (req, res, next) => {
  const events = await prisma.event.findMany({
    where: { organizerId: req.user!.id },
    orderBy: { startsAt: "asc" },
  });

  res.json({ success: true, data: events });
});
```

The `where` clause is the authorization. An admin route can list all events later; an organizer route must not.

## Time-zone verification

Add a test that formats a stored instant in the event zone:

```ts
const instant = new Date("2026-03-08T23:00:00.000Z"); // 7:00 p.m. EDT
const formatted = new Intl.DateTimeFormat("en-US", {
  timeZone: "America/New_York",
  hour: "numeric",
  minute: "2-digit",
}).format(instant);

expect(formatted).toBe("7:00 PM");
```

Also test a winter date to prove the offset changes. If you store a fixed offset instead of an IANA zone, this test fails.

## Verify

- Creating an event without a title returns `400` with a field error.
- An invalid IANA zone returns `400`.
- Sales ending after the event starts returns `400`.
- Two events with the same title get different slugs.
- Organizer A cannot see Organizer B's events in `GET /organizer/events`.
- The public page shows the event time in the event's zone, not the server's zone.

## Key ideas

- Store instants in UTC and the event's IANA zone.
- Validate the event payload on the API, not only in the form.
- Generate unique slugs with a random suffix.
- Organizer queries are scoped by `organizerId` from the session.
