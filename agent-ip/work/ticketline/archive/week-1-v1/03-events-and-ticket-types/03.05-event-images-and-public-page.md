## The image in the database

A first version stores the cover image as a base64 string in the event row. The page is slow, every query drags the image, backups balloon, and the browser caches nothing useful. The database is a terrible blob store.

Ticketline stores image bytes in object storage and keeps only a key in PostgreSQL:

```
events.cover_image_key = "events/evt_123/8f3c.webp"
```

The public page resolves that key to a URL. The database stays small; the CDN does the heavy lifting.

<BigWordAlert
  term="Presigned URL"
  plainEnglish="A temporary URL that grants permission to upload or read one object without exposing your storage credentials."
  whyItMatters="The browser uploads directly to storage with a short-lived URL. The API never proxies the file and never ships the secret key."
/>

## Storage configuration

Add the S3 client to the API:

```bash
pnpm --filter api add @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

```ts
import { S3Client } from "@aws-sdk/client-s3";
import { env } from "./config.js";

export const s3 = new S3Client({
  region: env.S3_REGION,
  endpoint: env.S3_ENDPOINT,
  forcePathStyle: true, // required for MinIO
  credentials: {
    accessKeyId: env.S3_ACCESS_KEY,
    secretAccessKey: env.S3_SECRET_KEY,
  },
});
```

Add `S3_PUBLIC_URL` to the environment. In local development, it points at MinIO; in production, at a CDN or public bucket URL.

## Presign the upload

```ts
import { randomUUID } from "node:crypto";
import { PutObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const allowed = new Map([
  ["image/jpeg", "jpg"],
  ["image/png", "png"],
  ["image/webp", "webp"],
]);

organizerEventRouter.post("/events/:id/cover-upload", async (req, res, next) => {
  try {
    const event = await loadOwnedEvent(req.user!, req.params.id);
    const contentType = String(req.body?.contentType ?? "");
    const extension = allowed.get(contentType);

    if (!extension) {
      return res.status(400).json({
        success: false,
        message: "Use a JPEG, PNG, or WebP image.",
        code: "UNSUPPORTED_IMAGE_TYPE",
      });
    }

    const key = `events/${event.id}/${randomUUID()}.${extension}`;
    const command = new PutObjectCommand({
      Bucket: env.S3_BUCKET,
      Key: key,
      ContentType: contentType,
    });

    const uploadUrl = await getSignedUrl(s3, command, { expiresIn: 300 });

    res.json({ success: true, data: { uploadUrl, key } });
  } catch (error) {
    next(error);
  }
});
```

The key is generated by the server, not the client. A client-supplied key could overwrite another event's image.

After the upload, set the key on the event through a dedicated endpoint. Validate that the key starts with `events/${event.id}/` before saving it. A presigned PUT does not enforce a maximum file size; for a production cap, use a presigned POST policy or a storage rule. The course states this limitation rather than pretending the upload is fully constrained.

## Public page

The public page has one job: help a buyer decide whether to attend and what to buy.

```tsx
export default async function EventPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const response = await fetch(`${process.env.API_URL}/api/v1/events/${slug}`, {
    cache: "no-store",
  });

  if (!response.ok) notFound();

  const { data: event } = await response.json();
  const starts = new Intl.DateTimeFormat("en-US", {
    dateStyle: "full",
    timeStyle: "short",
    timeZone: event.timezone,
  }).format(new Date(event.startsAt));

  return (
    <main className="mx-auto max-w-3xl px-6 py-12">
      {event.coverImageKey ? (
        <img
          src={`${process.env.S3_PUBLIC_URL}/${event.coverImageKey}`}
          alt={`${event.title} cover`}
          className="mb-8 aspect-[16/9] w-full rounded-2xl object-cover"
        />
      ) : null}

      <h1 className="text-4xl font-semibold tracking-tight">{event.title}</h1>
      <p className="mt-2 text-muted-foreground">{starts} · {event.venueName}</p>
      <p className="mt-6 text-lg leading-relaxed">{event.description}</p>

      <section className="mt-10 space-y-4">
        <h2 className="text-xl font-semibold">Tickets</h2>
        {event.ticketTypes.map((type: { id: string; name: string; priceCents: number; available: number; soldOut: boolean }) => (
          <div key={type.id} className="flex items-center justify-between rounded-xl border p-4">
            <div>
              <p className="font-medium">{type.name}</p>
              <p className="text-sm text-muted-foreground">
                {type.soldOut ? "Sold out" : `${type.available} available`}
              </p>
            </div>
            <p className="font-mono">${(type.priceCents / 100).toFixed(2)}</p>
          </div>
        ))}
      </section>
    </main>
  );
}
```

Accessibility and mobile checks:

- The image has descriptive alt text.
- The heading order is `h1` then `h2`.
- The ticket rows are readable at a narrow width.
- The price is formatted with two decimals.
- Sold-out is text, not only a color.
- The page has a clear primary action in Week 2; for now, the ticket list is the call to action.

## Verify

- An image upload returns a presigned URL and a server-generated key.
- Uploading with `image/gif` returns `400`.
- The saved key belongs to the event's prefix.
- The public page shows the cover, title, local time, venue, description, and ticket types.
- A draft event's slug returns `404`.
- The page is readable at 375px width and with keyboard navigation.

## Key ideas

- Store image bytes in object storage; store the key in the database.
- Presigned uploads keep storage credentials on the server.
- Validate content type and key prefix.
- The public page is a product surface: local time, clear tiers, accessible and mobile.
