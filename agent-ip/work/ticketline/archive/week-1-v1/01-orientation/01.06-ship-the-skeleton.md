## The first deploy is a debugging tool

A skeleton that runs locally but has never been deployed hides a category of problems: environment variables, build commands, database URLs, CORS, cookies, and cold starts. You do not want to discover those in Week 4 while trying to demo the last-ticket race.

This chapter builds the smallest production-shaped slice: a web page that calls the API, and an API health route that proves the database connection works. It is not the product yet. It is the floor you will build on.

### `src/config.ts`

Validate the environment once at boot. A missing `DATABASE_URL` should fail with a readable message, not a stack trace inside the first request.

```ts
import "dotenv/config";
import { z } from "zod";

const schema = z.object({
  NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
  PORT: z.coerce.number().int().positive().default(4000),
  DATABASE_URL: z.string().min(1, "DATABASE_URL is required"),
  WEB_ORIGIN: z.string().url().default("http://localhost:3000"),
  LOG_LEVEL: z.enum(["fatal", "error", "warn", "info", "debug", "trace", "silent"]).default("info"),
});

export const env = schema.parse(process.env);
```

### `src/db.ts`

Prisma 7 needs a driver adapter at runtime. One client per process is enough for this app.

```ts
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "./generated/prisma/index.js";
import { env } from "./config.js";

const adapter = new PrismaPg({
  connectionString: env.DATABASE_URL,
});

export const prisma = new PrismaClient({ adapter });
```

### `src/logger.ts`

Structured logs are part of the production bar. Do not use `console.log` for request logs.

```ts
import pino from "pino";
import { env } from "./config.js";

export const logger = pino({ level: env.LOG_LEVEL });
```

### `src/routes/health.ts`

The health route must prove the database connection, not only that the process is alive.

```ts
import { Router } from "express";
import { prisma } from "../db.js";

export const healthRouter = Router();

healthRouter.get("/health", async (_req, res, next) => {
  try {
    await prisma.$queryRaw`SELECT 1`;
    res.json({ status: "ok", timestamp: new Date().toISOString() });
  } catch (error) {
    next(error);
  }
});
```

### `src/middleware/error-handler.ts`

Use one error envelope everywhere. The browser should never receive a raw stack trace.

```ts
import type { ErrorRequestHandler, RequestHandler } from "express";
import { logger } from "../logger.js";

export const notFoundHandler: RequestHandler = (req, res) => {
  res.status(404).json({
    success: false,
    message: `Cannot ${req.method} ${req.path}`,
    code: "NOT_FOUND",
  });
};

export const errorHandler: ErrorRequestHandler = (error, req, res, _next) => {
  logger.error({ err: error, method: req.method, url: req.originalUrl }, "request failed");
  res.status(500).json({
    success: false,
    message: "Something went wrong on our end.",
    code: "INTERNAL",
  });
};
```

### `src/app.ts`

Keep the app factory separate from the process start. This is what makes supertest possible.

```ts
import express from "express";
import cors from "cors";
import helmet from "helmet";
import cookieParser from "cookie-parser";
import { pinoHttp } from "pino-http";
import { env } from "./config.js";
import { logger } from "./logger.js";
import { healthRouter } from "./routes/health.js";
import { errorHandler, notFoundHandler } from "./middleware/error-handler.js";

export function createApp() {
  const app = express();

  app.disable("x-powered-by");
  app.use(helmet());
  app.use(cors({ origin: env.WEB_ORIGIN, credentials: true }));
  app.use(express.json({ limit: "1mb" }));
  app.use(cookieParser());
  app.use(pinoHttp({ logger }));

  app.use(healthRouter);

  app.use(notFoundHandler);
  app.use(errorHandler);

  return app;
}
```

### `src/index.ts`

```ts
import { createApp } from "./app.js";
import { env } from "./config.js";
import { prisma } from "./db.js";
import { logger } from "./logger.js";

async function start() {
  await prisma.$connect();
  const app = createApp();
  app.listen(env.PORT, () => {
    logger.info({ port: env.PORT, env: env.NODE_ENV }, "Ticketline API listening");
  });
}

start().catch((error) => {
  logger.fatal({ err: error }, "failed to start");
  process.exit(1);
});
```

## The web connection

The browser should call a same-origin path (`/api/...`), and Next.js should proxy it to the API. That keeps cookies simple in development and gives you one place to change the API URL in production.

`apps/web/next.config.ts`:

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  async rewrites() {
    return [
      {
        source: "/api/:path*",
        destination: `${process.env.API_URL}/api/:path*`,
      },
    ];
  },
};

export default nextConfig;
```

Add `API_URL=http://localhost:4000` to `apps/web/.env.local`.

A minimal home page that proves the path works:

```tsx
export default async function HomePage() {
  const response = await fetch(`${process.env.API_URL}/health`, { cache: "no-store" });
  const health = await response.json();

  return (
    <main className="mx-auto flex min-h-screen max-w-2xl flex-col justify-center gap-4 p-8">
      <p className="text-sm font-medium uppercase tracking-widest text-muted-foreground">
        Ticketline
      </p>
      <h1 className="text-4xl font-semibold tracking-tight">
        The last ticket should not be sold twice.
      </h1>
      <p className="text-lg text-muted-foreground">
        API status: <span className="font-mono">{health.status}</span>
      </p>
    </main>
  );
}
```

## One health test

Create `apps/api/src/routes/health.test.ts`:

```ts
import request from "supertest";
import { describe, expect, it } from "vitest";
import { createApp } from "../app.js";

describe("GET /health", () => {
  it("returns ok when the database is reachable", async () => {
    const response = await request(createApp()).get("/health");

    expect(response.status).toBe(200);
    expect(response.body.status).toBe("ok");
  });
});
```

## CI

Add `.github/workflows/ci.yml`:

```yaml
name: ci

on:
  push:
  pull_request:

jobs:
  api:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: ticketline
          POSTGRES_PASSWORD: ticketline
          POSTGRES_DB: ticketline
        ports: ["5432:5432"]
        options: >-
          --health-cmd "pg_isready -U ticketline"
          --health-interval 5s
          --health-timeout 3s
          --health-retries 10
    env:
      DATABASE_URL: postgresql://ticketline:ticketline@localhost:5432/ticketline
      WEB_ORIGIN: http://localhost:3000
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter api prisma generate
      - run: pnpm --filter api typecheck
      - run: pnpm --filter api test
```

The first CI job does not need Redis or MinIO because the skeleton does not use them yet. Add those services when the code needs them.

3. Add `apps/web/.env.local` with `API_URL=http://localhost:4000`.
4. Start the API and the web app in separate terminals.
5. Run the health test.

## Verify

- `curl http://localhost:4000/health` returns `200` with `status: "ok"`.
- The web page shows `API status: ok`.
- `pnpm --filter api typecheck` passes.
- `pnpm --filter api test` passes.
- CI is green.
- `.env` files are not tracked by Git.

## Common failures

| Symptom | Likely cause |
|---|---|
| `DATABASE_URL is required` | `apps/api/.env` is missing or the API is running from the wrong directory |
| `Cannot find module './generated/prisma/index.js'` | `prisma generate` has not run |
| `ECONNREFUSED 5432` | Postgres is not running; run `docker compose up -d` |
| Web page shows `fetch failed` | `API_URL` is missing or the API is not running |
| CORS error in the browser | The request is going directly to `:4000` instead of the same-origin `/api` proxy |
