## The demo that hid a broken logout

A learner demos the app: signup works, login works, the organizer dashboard loads. Nobody clicks logout. Later, a mentor discovers that logout cleared the cookie but left the session row valid. A stolen token still works.

The test below would have caught it:

```ts
await agent.post("/api/v1/auth/logout").expect(204);
await agent.get("/api/v1/auth/me").expect(401);
```

The demo proves the happy path. The test proves the invariant.

Create `apps/api/src/test/helpers.ts`:

```ts
import request from "supertest";
import { prisma } from "../db.js";
import { createApp } from "../app.js";

export const app = () => createApp();

export async function resetDatabase() {
  // Week 1 tables. Add new child tables here when their models arrive.
  await prisma.ticketType.deleteMany();
  await prisma.event.deleteMany();
  await prisma.organizerProfile.deleteMany();
  await prisma.emailVerificationToken.deleteMany();
  await prisma.session.deleteMany();
  await prisma.user.deleteMany();
}

export function agent() {
  return request.agent(app());
}

export async function signupAndLogin(email = "ada@example.test") {
  const a = agent();
  const response = await a
    .post("/api/v1/auth/signup")
    .send({ email, name: "Ada", password: "correct horse battery staple" })
    .expect(201);
  return { agent: a, user: response.body.data };
}
```

The delete order matters: children before parents. Week 1 does not have holds, orders, tickets, or scans yet. Add those `deleteMany` calls when their models arrive in Week 2 so the helper keeps compiling.

## Auth tests

```ts
import { beforeEach, describe, expect, it } from "vitest";
import { agent, resetDatabase, signupAndLogin } from "../test/helpers.js";

beforeEach(resetDatabase);

describe("auth", () => {
  it("signs up, returns the user, and sets a cookie", async () => {
    const a = agent();
    const response = await a
      .post("/api/v1/auth/signup")
      .send({ email: "ada@example.test", name: "Ada", password: "correct horse battery staple" })
      .expect(201);

    expect(response.body.data.email).toBe("ada@example.test");
    expect(response.headers["set-cookie"]?.[0]).toContain("tl_session=");
    expect(response.headers["set-cookie"]?.[0]).toContain("HttpOnly");
  });

  it("rejects a wrong password with a generic 401", async () => {
    const { agent: a } = await signupAndLogin();
    await a.post("/api/v1/auth/logout").expect(204);

    const response = await a
      .post("/api/v1/auth/login")
      .send({ email: "ada@example.test", password: "wrong" })
      .expect(401);

    expect(response.body.message).toBe("Invalid email or password.");
  });

  it("revokes the session on logout", async () => {
    const { agent: a } = await signupAndLogin();
    await a.get("/api/v1/auth/me").expect(200);
    await a.post("/api/v1/auth/logout").expect(204);
    await a.get("/api/v1/auth/me").expect(401);
  });
});
```

Add a session-expiry test by inserting a session with `expiresAt` in the past and calling `/me` with that cookie. The assertion is `401`, and the expired row should be deleted.

## Role and ownership tests

For the role matrix, you need an organizer. The helper can sign up, verify the email directly in the database, and call onboarding:

```ts
export async function makeOrganizer(email: string) {
  const { agent: a, user } = await signupAndLogin(email);

  await prisma.user.update({
    where: { id: user.id },
    data: { emailVerifiedAt: new Date() },
  });

  await a
    .post("/api/v1/organizer/onboarding")
    .send({ displayName: "Ada Events" })
    .expect(201);

  return { agent: a, user };
}
```

Unit-test the ownership function directly:

```ts
import { describe, expect, it } from "vitest";
import { assertEventOwner } from "../events/access.js";

const organizer = { id: "u1", role: "ORGANIZER" } as const;
const other = { id: "u2", role: "ORGANIZER" } as const;
const admin = { id: "u3", role: "ADMIN" } as const;
const event = { id: "e1", organizerId: "u1" } as never;

describe("assertEventOwner", () => {
  it("allows the owner", () => expect(assertEventOwner(organizer as never, event)).toBe(event));
  it("rejects another organizer", () => expect(() => assertEventOwner(other as never, event)).toThrow());
  it("allows an admin", () => expect(assertEventOwner(admin as never, event)).toBe(event));
  it("rejects a missing event", () => expect(() => assertEventOwner(organizer as never, null)).toThrow());
});
```

Add an integration test once the event update route exists:

```ts
const { agent: owner } = await makeOrganizer("owner@example.test");
const { agent: other } = await makeOrganizer("other@example.test");

const created = await owner
  .post("/api/v1/organizer/events")
  .send({ title: "Last Ticket", /* ... */ })
  .expect(201);

await other
  .patch(`/api/v1/organizer/events/${created.body.data.id}`)
  .send({ title: "Stolen" })
  .expect(403);
```

## Verify

- `pnpm --filter api test` passes.
- A second run passes without manual cleanup.
- The tests use the test database, not development.
- A failing assertion produces a readable message.

## Module 2 gate

- [ ] Signup, login, logout, and /me work end-to-end.
- [ ] Wrong password and unknown email return the same 401 response.
- [ ] Logout deletes the session row; the old cookie no longer works.
- [ ] Attendee, owner, other organizer, and admin behavior matches the permission matrix.
- [ ] Onboarding requires a verified email and creates exactly one organizer profile.
- [ ] The auth test suite passes in CI.
