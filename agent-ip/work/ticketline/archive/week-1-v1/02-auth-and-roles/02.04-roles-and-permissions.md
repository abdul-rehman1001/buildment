## The route that trusted the role

An organizer route is protected with `requireRole("ORGANIZER")`. An organizer sends a request for another organizer's event. The role check passes; the event ID is accepted; the update succeeds. The API was authenticated and role-authorized, but not object-authorized.

This is the same IDOR failure from 1.2, now in code. The fix is a second check after the object is loaded.

## Three checks, in order

```text
authenticate     → who is making the request?
requireRole      → is this kind of user allowed on this route?
assertOwnership  → does this user own this specific object?
```

Skipping the first makes the others meaningless. Skipping the third makes the second insufficient.

## Error classes

Create `apps/api/src/errors.ts`:

```ts
export class HttpError extends Error {
  constructor(
    readonly status: number,
    message: string,
    readonly code: string
  ) {
    super(message);
  }
}

export const unauthorized = (message = "Not signed in.") =>
  new HttpError(401, message, "AUTH_REQUIRED");

export const forbidden = (message = "You do not have permission to do that.", code = "FORBIDDEN") =>
  new HttpError(403, message, code);

export const notFound = (message = "Not found.") =>
  new HttpError(404, message, "NOT_FOUND");
```

Update the error handler to return `error.status` and `error.code` for `HttpError`, and `500` for anything else.

## Middleware

Create `apps/api/src/auth/authorize.ts`:

```ts
import type { RequestHandler } from "express";
import type { Role } from "../generated/prisma/index.js";
import { forbidden, unauthorized } from "../errors.js";

export const requireAuth: RequestHandler = (req, _res, next) => {
  if (!req.user) return next(unauthorized());
  next();
};

export function requireRole(...roles: Role[]): RequestHandler {
  return (req, _res, next) => {
    if (!req.user) return next(unauthorized());
    if (!roles.includes(req.user.role)) {
      return next(forbidden("This route requires a different role.", "ROLE_REQUIRED"));
    }
    next();
  };
}
```

Use `requireRole("ORGANIZER", "ADMIN")` on organizer routes. Notice that the middleware does not load an event and cannot prove ownership.

## Ownership

Create `apps/api/src/events/access.ts`:

```ts
import type { Event, User } from "../generated/prisma/index.js";
import { forbidden, notFound } from "../errors.js";
import { prisma } from "../db.js";

export function assertEventOwner(user: User, event: Event | null): Event {
  if (!event) throw notFound("Event not found.");
  if (user.role !== "ADMIN" && event.organizerId !== user.id) {
    throw forbidden("You do not own this event.", "NOT_EVENT_OWNER");
  }
  return event;
}

export async function loadOwnedEvent(user: User, eventId: string) {
  const event = await prisma.event.findUnique({ where: { id: eventId } });
  return assertEventOwner(user, event);
}
```

The order matters: load the event, then check ownership, then write. Do not accept `organizerId` from the request body. The owner comes from the session; the event comes from the database.

## Route usage

```ts
import { Router } from "express";
import { requireAuth, requireRole } from "../auth/authorize.js";
import { loadOwnedEvent } from "../events/access.js";

export const organizerEventRouter = Router();

organizerEventRouter.use(requireAuth, requireRole("ORGANIZER", "ADMIN"));

organizerEventRouter.patch("/events/:id", async (req, res, next) => {
  try {
    const event = await loadOwnedEvent(req.user!, req.params.id);
    // validate body, then update event
    res.json({ success: true, data: event });
  } catch (error) {
    next(error);
  }
});
```

The handler is short because the authorization is explicit and testable. The route cannot accidentally skip the ownership check if every handler uses `loadOwnedEvent`.

## The permission matrix

Keep `docs/permissions.md` current. For Week 1:

| Endpoint | Attendee | Organizer (owner) | Organizer (other) | Gate staff | Admin |
|---|---|---|---|---|---|
| `GET /events` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `POST /organizer/events` | 403 | ✓ | ✓ | 403 | ✓ |
| `PATCH /organizer/events/:id` | 403 | ✓ | 403 | 403 | ✓ |
| `POST /organizer/events/:id/publish` | 403 | ✓ | 403 | 403 | ✓ |
| `GET /organizer/events` | 403 | own only | own only | 403 | all |

## Verify

- No session → `401`.
- Attendee on an organizer route → `403`.
- Organizer on another organizer's event → `403 NOT_EVENT_OWNER`.
- Owner → succeeds.
- Admin → succeeds on any event.
- Changing `organizerId` in the request body has no effect.

## Key ideas

- Authenticate, authorize the role, load the object, authorize ownership.
- Never take ownership from the request body.
- A reusable `loadOwnedEvent` makes the check hard to skip.
- The permission matrix is a design artifact and a test plan.
