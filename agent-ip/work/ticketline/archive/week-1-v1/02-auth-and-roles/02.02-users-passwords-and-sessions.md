## Passwords are not encrypted

Encryption is reversible. Password hashing is not. If an attacker steals the database, a password hash should be expensive to attack and the plaintext should not be recoverable.

Ticketline uses **Argon2id**, the current recommended password-hashing function. It is memory-hard, which makes GPU and ASIC attacks more expensive. The parameters matter: too little memory and the hash is cheap to attack; too much and login becomes a denial-of-service vector. Start with the library defaults, measure login latency, and document the trade-off.

## Password module

Create `apps/api/src/auth/password.ts`:

```ts
import argon2 from "argon2";

export function hashPassword(password: string) {
  return argon2.hash(password, { type: argon2.argon2id });
}

export function verifyPassword(hash: string, password: string) {
  return argon2.verify(hash, password);
}
```

Two rules:

- Never log the password or the hash.
- On login, if the email is unknown, still perform a dummy hash verification so the response time does not reveal whether the account exists. Timing is a side channel.

## Session module

Create `apps/api/src/auth/session.ts`:

```ts
import { createHash, randomBytes } from "node:crypto";

export const SESSION_COOKIE = "tl_session";
export const SESSION_TTL_MS = 30 * 24 * 60 * 60 * 1000;

export function createSessionToken() {
  return randomBytes(32).toString("base64url");
}

export function hashSessionToken(token: string) {
  return createHash("sha256").update(token).digest("hex");
}

export function sessionExpiry(now = Date.now()) {
  return new Date(now + SESSION_TTL_MS);
}
```

The raw token is returned to the caller exactly once, to set the cookie. The database stores only `hashSessionToken(token)`.

## Cookie module

Create `apps/api/src/auth/cookie.ts`:

```ts
import type { Response } from "express";
import { SESSION_COOKIE, SESSION_TTL_MS } from "./session.js";
import { env } from "../config.js";

const baseOptions = {
  httpOnly: true,
  sameSite: "lax" as const,
  secure: env.NODE_ENV === "production",
  path: "/",
};

export function setSessionCookie(res: Response, token: string) {
  res.cookie(SESSION_COOKIE, token, { ...baseOptions, maxAge: SESSION_TTL_MS });
}

export function clearSessionCookie(res: Response) {
  res.clearCookie(SESSION_COOKIE, baseOptions);
}
```

## Authenticate middleware

Create `apps/api/src/auth/authenticate.ts`:

```ts
import type { RequestHandler } from "express";
import { prisma } from "../db.js";
import { SESSION_COOKIE, hashSessionToken } from "./session.js";

export const authenticate: RequestHandler = async (req, _res, next) => {
  try {
    const token = req.cookies?.[SESSION_COOKIE];
    if (!token) return next();

    const session = await prisma.session.findUnique({
      where: { tokenHash: hashSessionToken(token) },
      include: { user: true },
    });

    if (!session || session.expiresAt <= new Date()) {
      if (session) {
        await prisma.session.delete({ where: { id: session.id } }).catch(() => undefined);
      }
      return next();
    }

    req.user = session.user;
    req.sessionId = session.id;
    next();
  } catch (error) {
    next(error);
  }
};
```

This middleware attaches the user when a valid session exists. It does **not** reject missing sessions; a separate `requireAuth` middleware does that in 2.4. Keeping the two concerns separate makes it easy to support optional auth on public routes.

Extend the Express request type in `apps/api/src/types/express.d.ts`:

```ts
import type { User } from "../generated/prisma/index.js";

declare global {
  namespace Express {
    interface Request {
      user?: User;
      sessionId?: string;
    }
  }
}

export {};
```

## Session creation and revocation

Create `apps/api/src/auth/create-session.ts`:

```ts
import { prisma } from "../db.js";
import { createSessionToken, hashSessionToken, sessionExpiry } from "./session.js";

export async function createSession(userId: string) {
  const token = createSessionToken();
  const expiresAt = sessionExpiry();

  await prisma.session.create({
    data: {
      tokenHash: hashSessionToken(token),
      userId,
      expiresAt,
    },
  });

  return { token, expiresAt };
}

export async function revokeSession(sessionId: string) {
  await prisma.session.deleteMany({ where: { id: sessionId } });
}

export async function revokeAllSessions(userId: string) {
  await prisma.session.deleteMany({ where: { userId } });
}
```

`revokeAllSessions` is useful after a password change or a suspected compromise. The course adds it to the change-password flow in Week 4.

## Verify

- A password hash is different every time the same password is hashed (random salt).
- `verifyPassword(hash, correct)` returns true; `verifyPassword(hash, wrong)` returns false.
- Two sessions for the same user have different token hashes.
- An expired session is rejected and deleted.
- The raw token never appears in the database: `SELECT token_hash FROM sessions` shows hashes only.

## Key ideas

- Passwords use Argon2id, not reversible encryption.
- Session tokens are random, hashed at rest, and stored in an HttpOnly cookie.
- `authenticate` attaches the user; `requireAuth` rejects missing sessions.
- Revocation is a database delete, which is the point of sessions.
